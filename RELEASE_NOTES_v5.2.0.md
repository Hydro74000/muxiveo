# Version Française

## Nouveautés

* **Débruitage MVO-R2 (moteur vidéo MVO 1.15.0).** Nouveau débruiteur appris, proposé par défaut dans le filtre « Débruitage » du panneau Encodage (NLMeans reste disponible au choix). Chaque image est débruitée à partir d'une fenêtre de 5 images recalées par le flux optique du réseau : le grain et le bruit sont retirés, le détail confirmé par les images voisines est gardé.
  * **Niveaux** : *Auto* (dosage décidé plan par plan d'après le grain mesuré : une source propre est à peine touchée), *Léger*, *Moyen*, *Fort*. Contenu animé (genre « Animation » de la fiche TMDB, ou réglage manuel) : l'Auto retire un cran de plus.
  * **Compensation de netteté** (liste « Netteté », active par défaut) : rend une partie du détail fin que le débruitage a retiré, seulement là où il est stable d'une image à l'autre — jamais le grain, jamais plus que ce qui a été retiré.
  * **Mode Auto (par défaut)** : mode rapide au-delà de 2560 px de large — en UHD, il garde le même détail que le mode normal pour environ un tiers de temps en moins — et mode normal en dessous. Mode rapide : flux optique calculé au quart de la définition.
  * **HDR** : traitement en 10 bits ; MaxCLL / MaxFALL de la source conservés quand le débruitage ne les change pas de façon visible, sinon mesurés sur l'image débruitée ; Dolby Vision et HDR10+ copiés puis contrôlés image par image ; compatible avec l'intégration de la couche Dolby Vision FEL.
  * **Débruitage puis interpolation** dans le même passage quand MVO-RIFE est aussi actif.
  * **NVIDIA TensorRT** : débruitage accéléré avec l'extension `mvo-rife-trt` 1.3.0 (repli Vulkan automatique).
  * MVO-R2 est un traitement exigeant : en 4K, c'est lui qui fixe la vitesse de la chaîne d'encodage.
* **HDR10+ généré depuis le Dolby Vision.** Nouvelle case du panneau Encodage « Générer les métadonnées HDR10+ depuis le Dolby Vision », proposée pour toute source Dolby Vision à image de base PQ, avec tous les codecs qui portent le HDR10+ (x265, NVENC, QSV, VAAPI, AMF, NVEncC HEVC et AV1) et en **Copy** (flux patché sans réencodage : RPU, couche d'amélioration et signalisation Dolby Vision intacts). Pour les TV sans Dolby Vision (Samsung…).
  * **Valeurs mesurées** : statistiques de chaque image (MaxScl, moyenne, distribution, profil A) mesurées par l'extension `mvo-fel`, une scène par plan Dolby Vision, avec les règles du HDR10+ recalculé de l'intégration FEL ; mesure reprise du cache du HDR Studio quand elle existe. Intégration FEL active : image reconstruite. Sans extension ou source P5 : estimation depuis le L1 du RPU, signalée comme approximative.
  * **Pics isolés** : le MaxScl ne suit plus les quelques pixels qui dépassent nettement le reste de l'image (au-delà de 2 × le percentile 99,98 % et de 1000 nits) ; sur une TV de 600 nits, les hautes lumières d'un plan ne sont plus tassées par un reflet ponctuel. Même règle pour le HDR10+ recalculé de l'intégration FEL et le recalcul du HDR Studio ; le réalignement du HDR Studio ne signale plus ces pixels isolés comme un écrêtage.
  * **Remplace** le HDR10+ de la source (exclusive avec « Copier les métadonnées HDR10+ ») ; compatible avec les filtres, MVO-R2, MVO-RIFE (métadonnées étendues à la cadence produite) et l'intégration FEL ; trames contrôlées avant l'injection. Exceptions, comme pour la copie HDR10+ : NVEncC n'accepte pas les filtres passant par FFmpeg (deblock, chroma_smooth, recadrage ou redimensionnement en %) hors intégration FEL — choisir un encodeur FFmpeg (x265, NVENC…) ; en Copy, une source HEVC brute (`.hevc`, `.h265`…) est refusée faute d'horodatage — la remuxer d'abord en MKV ou réencoder.
  * **CLI / API** : `--hdr10plus generate`, `hdr10plus.mode: generate` du bloc `encode`, presets d'encodage.
* **Désentrelacement YADIF « une image par champ » sans interpolation** : les métadonnées Dolby Vision / HDR10+ copiées suivent désormais le doublement des images (elles n'en couvraient que la moitié), aussi avec le filtre natif de NVEncC.
* **Extension « Moteur vidéo MVO (débruitage, interpolation) ».** L'extension `mvo-rife` porte désormais les deux traitements ; la page Extensions la présente sous ce nom.
* **Variante AllInc NoVidia et NVEncC dans Extensions.** Nouveaux paquets `Muxiveo-x86_64_allinc_novidia-<version>.AppImage` et `Muxiveo-Setup-AllInc_NoVidia-<version>.exe` : identiques à l'AllInc, sans NVEncC, installé au premier lancement si un GPU NVIDIA est détecté (Linux : apt / dnf avec mot de passe administrateur, sinon dossier utilisateur, notamment sur les distributions immuables ; Windows : dossier utilisateur). NVEncC s'installe, se met à jour et se supprime aussi depuis la carte « NVEncC » de la page Extensions.
* **x265 : réglage *frame-threads*** (nombre d'images encodées en parallèle, automatique par défaut). Le nombre de fils FFmpeg n'est plus appliqué à libx265, qui occupe toujours tous les cœurs (limite par `pools=N` dans les paramètres de la piste).
* **x265 : nouveaux paramètres avancés** : `qg-size`, `deblock`, `qcomp`, `cbqpoffs` / `crqpoffs`, `b-intra`, `rc-lookahead` ; les options désactivées (`no-…`) et les valeurs hors des bornes des contrôles sont relues et conservées.
* **Échec d'encodage avec fichiers temporaires.** Quand un encodage lancé depuis l'interface échoue après avoir produit des fichiers, une fenêtre propose de conserver le dossier de travail pour examen ; sinon il est supprimé en arrière-plan.
* **Aperçu image encodé.** L'aperçu image du panneau Encodage montre désormais l'image de la **sortie encodée** à l'instant choisi (ou tiré au hasard), avec tous les réglages de la piste (filtres, recadrage, redimensionnement, HDR, FEL, MVO-R2, interpolation), au lieu de la galerie de sept scènes de la source ; l'image montrée est la première à partir de cet instant, d'après ses horodatages réels. Même aperçu en CLI (`encode --preview-image`) et dans l'API.
* **Paramètres en onglets.** Une section par onglet (Interface, Encodage audio, Synchronisation, Métadonnées, Chemins, Outils externes, FFmpeg, Encodage, Muxage Matroska), champs à la taille de leur contenu, et un seul bouton « Enregistrer » pour l'onglet modifié, signalé par une pastille. Quitter l'onglet ou la page avec des modifications non enregistrées — y compris en lançant une opération, en déposant un fichier, en installant une mise à jour, en redémarrant, en rechargeant `config.ini` ou en fermant l'application — propose de les enregistrer, de les ignorer ou d'annuler (rien n'est alors lancé). Seules les valeurs modifiées sont écrites, les autres gardent leur provenance ; une valeur de `config.ini` que le champ ne sait pas afficher (hors paliers, option inconnue, hors bornes) est conservée telle quelle tant qu'on n'y touche pas. Un chemin d'outil enregistré vaut pour le traitement suivant (encodage, Merge DoVi), sans redémarrage.
* **Options sans effet retirées.** `[tools] eac3to`, utilisé par aucun traitement (il n'est plus signalé comme outil manquant au tableau de bord ni au démarrage), `[hdr] dovi_profile` / `dovi_compat_id`, déjà signalés inutilisés, et `[encoding] ram_buffer_enabled` (le buffer RAM n'était plus utilisé : l'option ne changeait qu'un message du journal) quittent les Paramètres, la commande `config` du CLI, l'opération `system.tools` et le setup ; leurs lignes sont retirées de `config.ini` au prochain enregistrement de la configuration. « Seuil buffer RAM » devient « Réserve de RAM libre » : part de la RAM gardée libre pour lancer un encodage vidéo de plus en parallèle. Le pic de l'écran simulé (onglet HDR) se règle dans HDR Studio (onglet Luminance), qui retient le dernier choix ; une clé `[hdr] display_peak_nits` de `config.ini`, qui masquait ce choix au redémarrage, est ignorée.
* **CLI : couche de service et commande `call`.** Toutes les fonctions du CLI sont des opérations (56) au contrat stable, base du worker `serve` : `operations` liste le catalogue, `schema --version api` le publie en JSON, `call <opération> --request fichier.json` (ou `-` pour stdin) exécute une requête JSON stricte, job et bloc `encode` compris (erreurs détaillées par champ), et répond en JSON (état final et code retour d'un lot d'après son statut : 7 s'il n'a pas entièrement réussi). Nouveau format `--log-format events` : journal, progression et résultat en événements versionnés. Les sorties historiques des commandes sont inchangées, sauf les changements de compatibilité ci-dessous et un avertissement désormais émis pour une clé d'un job JSON hors du contrat (ce que le contrat acceptait reste accepté). Feuille de parité avec l'interface : `docs/cli/parite-gui.md`.
* **CLI : Ctrl+C annule proprement un remux ou un lot**, pendant la préparation (inspection, analyses de synchro, inspection HDR) comme pendant le traitement. `remux` / `run` / `profile apply` s'arrêtent comme une annulation depuis l'interface : processus arrêtés, fichier partiel et dossier de travail supprimés (code retour 6). Pendant un `batch`, le job en cours est annulé et le lot s'arrête ; les sorties déjà publiées restent et le résumé le signale (`cancelled`, code retour 7). Toutes les commandes du CLI sont désormais des opérations de la couche de service, appelables par `call` (lots : un job enfant par fichier, statut `succeeded` / `partial` / `failed` / `cancelled`). Ctrl+C annule aussi `inspect --hdr` (dès la lecture du fichier, mesure HDR et FEL Analyzer compris) et `hdr-patch`, et arrête `hybrid`.
* **CLI : encodage complet.** Nouvelle commande `encode` et bloc `encode` des jobs JSON (aussi pour `run`, `batch` et les profils) : codec et mode de débit, préréglage, profondeur, recadrage (dont la détection automatique), redimensionnement, filtres, débruitage MVO-R2, interpolation MVO-RIFE, HDR10 statique (source, saisi ou estimé), copie Dolby Vision / HDR10+, intégration FEL, tone mapping, réencodage audio, presets d'encodage de l'interface. Mêmes règles que le panneau Encodage (réglages par défaut selon la source, politique HDR par codec, preset incompatible refusé comme à son chargement) ; **rendu par défaut** : une source HDR encodée vers un codec sans HDR (H.264…) est convertie en SDR (tone mapping coché d'office, comme dans le panneau ; `tonemap.enabled: false` l'empêche), et les options HDR10 / Dolby Vision / HDR10+ retirées pour ce codec sont rétablies au retour sur un codec HDR ; `validate --json` publie le plan résolu et les mêmes refus qu'au lancement, `--dry-run` les commandes prévues. Nouvelle commande `capabilities` : encodeurs, préréglages, Vulkan, NVOF, TensorRT, moteur vidéo MVO. Aperçus image et vidéo encodés (`encode --preview-image` / `--preview-video`), presets d'encodage de l'interface gérés en CLI (`encode-preset list|show|save|import|export|delete`), dossier de travail d'un encodage en échec conservable (`--keep-failed-work-dir`).
* **Extraction de pistes, de couches Dolby Vision et de pièces jointes.** Clic droit dans le panneau Conteneur : « Extraire… » sur une piste audio ou de sous-titres, sous-menu « Extraire » sur une piste vidéo (flux vidéo, couche d'amélioration FEL / MEL et couche de base d'un Dolby Vision profil 7, RPU Dolby Vision, métadonnées HDR10+), « Extraire… » sur une pièce jointe embarquée. Flux élémentaire par défaut (HEVC / H.264 en Annex B, TrueHD, E-AC-3, DTS, FLAC, AAC…, PCM en WAV ou AIFF selon son format, sans conversion) ou Matroska au choix. Même extraction en CLI : nouvelle commande `extract` (`--track`, `--layer el|bl|rpu|hdr10plus`, `--attachment`, `--all`, `--format raw|mkv`) et opération `media.extract`. Chaque sortie est écrite dans un fichier `.partial` puis publiée : un échec ou une annulation ne laisse rien derrière (publication refusée par le système de fichiers ou destination modifiée entre-temps : résultat conservé et signalé).
* **CLI : HDR Studio complet.** Nouvelle commande `hdr-patch` (opération `hdr.patch`), équivalent de l'onglet Édition : MaxCLL/MaxFALL, écran de mastering, RPU Dolby Vision (L6, L5, L11, écran du RPU, retrait CM v4.0), HDR10+ (retrait, TSDML, profil A, plafond, recalcul depuis la mesure), valeurs proposées (`suggested`), « Garder identiques » et propositions de réalignement d'après la mesure (`--realign`), plan résolu sans écrire (`--dry-run`). `inspect --hdr --hdr-advice` ajoute les recommandations (valeurs proposées, simulation du tone mapping d'une TV avec `--hdr-display-peak` et `--hdr-tv-model`, réalignement), aussi dans le rapport HTML ; `--hdr-fel-moments` écrit les moments les plus marqués du FEL Analyzer en PNG pleine définition (sans FEL, avec FEL, écart).
* **CLI : synchro en chaîne et Synchro Studio.** Bloc `sources[i].sync` des jobs JSON : une source mesurée face à la piste d'une autre source suit la position de sa référence (références en chaîne composées, boucle refusée), mesure rapide ou approfondie, ou synchro donnée (calibration, décalage) ; `tracks[i].sync` synchronise une piste seule ; `--auto-sync-all` synchronise chaque source face à la première (`--auto-sync` inchangé). Nouvelle commande `calibration show|edit|compose|invert` : coupes, silences, jonctions retirées, décalage du départ ou depuis un segment, méthode de cadence (« auto » tranchée par l'analyse de hauteur), comme le Synchro Studio ; `sync-waveform` publie la forme d'onde d'une piste (données pour un client graphique).
* **CLI : `hybrid` sur le moteur du Hybrid Studio.** Sources à rôles (`--source master=…`, `donor-audio=…`, `donor-sub=…`, plusieurs donneurs ; `--ref`/`--donor`/`--ref-dir`/`--donor-dir` restent des alias), appariement par épisode, similarité ou ordre (`--matching`) et paires manuelles (`--pair`), recette exportée par le Studio (`--recipe`, nouveaux boutons « Exporter / Importer la recette… ») et langues / synchro en options, plan sans exécution (`--plan`, opération `hybrid.plan`, encodage résolu et validé par épisode comme au lancement) avec exact-jobs finalisés (`--export-jobs`, bloc `encode` conservé) et recette effective (`--save-recipe`), préparations en parallèle, encodage de chaque épisode (options d'encodage). **Changement :** la sélection par défaut est celle du Studio (audio du master en anglais, japonais ou VO ; audio et sous-titres français des donneurs) au lieu du retrait des seules pistes du donneur dans la langue de la référence ; une recette ou un profil la remplace.
* **CLI : TMDB, profils et Blu-ray.** `tmdb search` / `tmdb details` (fiche complète, titre de conteneur, balises MKV), gestion des profils décisionnels de l'interface (`profile list|show|save|delete`, `profile capture` d'après un job, comme « Capturer » du panneau Conteneur), `bluray-titles` (playlists d'un disque avant sélection).
* **CLI : administration.** `config path|show|get|set|unset|reset` (réglages du panneau Paramètres et des extensions, valeur effective et provenance : config.ini, réglage de l'interface ou défaut ; valeurs validées avant écriture), `workdir list|clean` (comme « Nettoyer » au démarrage : jobs actifs jamais touchés), `nvencc status|install|update|remove` (comme la carte NVEncC de la page Extensions ; `--no-sudo` : dossier utilisateur, sans aucune élévation).
* **CLI : installation des mises à jour.** `version --install --yes` télécharge, vérifie et installe la dernière version du canal (AppImage remplacée aussitôt ; installeur Windows, archive source et application macOS installés à la sortie du CLI), sans relancer l'interface ; compte rendu de la mise à jour précédente affiché.
* **CLI : aide complète et documentation.** Chaque option et chaque commande décrites (groupes Sources, Sortie, Pistes, Synchro, Encodage, HDR, TMDB, Journal ; valeurs par défaut ; exemples), page d'accueil par familles, commande `help` (`help COMMANDE`, `help --all`, `help --format md`), aide traduite selon la langue de l'interface. Référence générée `docs/cli/reference.md`, guide par tâche `docs/cli/README.md`, API `docs/cli/api.md` (opérations, événements, lots, erreurs), matrice de parité `docs/cli/parite-gui.md`. `operations --describe` indique aussi les événements émis.
* **API : worker `serve`.** `muxiveo --cli serve` est un point d'entrée machine local (JSON-RPC 2.0 sur stdio, un objet JSON par ligne) pour une extension ou un outil local lancé en processus enfant : soumission de jobs (`job.submit`), suivi en direct (`job.event`), annulation par identifiant (`job.cancel`), état (`job.get`, `job.list`), arrêt propre (`server.shutdown`). Jobs ordonnancés par nature : traitements de médias (`--max-jobs`, 1 par défaut), analyses servies pendant un long encodage (`--max-analyses`, 2), opérations de configuration exécutées seules. Après une mise à jour installée, le worker annonce son arrêt (`server.exiting`). Client d'exemple sans dépendance : `docs/cli/examples/serve_client.py` ; intégration Python : `JobManager` (`core.service`).
* **API : contrat typé.** `schema --version api` et `operations --describe` publient le schéma des documents (job, bloc `encode`, profil décisionnel, reliés par `$ref`, job fermé comme l'admission) et des résultats (fiche d'inspection et pistes, extraction, lots, réglages, presets, profils, capacités, extensions, TMDB…), la nature de chaque opération (`privileged`, `queue`) et, pour les événements, chaque variante : avertissements toujours à code (synchro à relire avec ses zones), étapes de progression à identifiant stable (`stage`) et libellé (`label`), progression de l'encodage (pourcentage, i/s, image, temps restant, piste, passe) identique à celle de l'interface ; dans les lots, chaque entrée indique son job enfant (`null` sans job enfant, ex. épisode Hybrid seulement exporté).
* **API : requêtes sûres.** Une requête de l'API (`call`, `serve`, Python) n'utilise jamais implicitement le dossier courant d'un worker (valeurs relatives depuis le dossier du fichier de requête — le dossier courant avec `call --request -` — ou le `base_dir` de la soumission, sinon refusées), refuse les chemins d'un autre OS, n'accepte d'un document aucun exécutable ni source de couverture hors de TMDB, et limite les paramètres libres de l'encodeur à ses propres options (entrées, sorties, formats, filtres, progression et chargeurs de fichiers d'options refusés).
* **Changements de compatibilité.** `call` exige `--allow-privileged` pour une opération privilégiée (`config.set/unset/reset`, `workdir.clean`, `nvencc.install/remove`, `plugins.install/update/remove`, `app.update_install`), sinon erreur `forbidden` (code retour 3) ; les commandes historiques (`config set`, `plugins install`…) ne changent pas. Sans cette autorisation, `config.show` / `config.get` masquent la clé et le token TMDB (`********`). Journal texte du CLI : les avertissements des traitements s'affichent `[WARNING]` (auparavant `[WARN]`).
* **Muxage Matroska natif par défaut (Remux, Encodage, Hybrid).** Le réglage « Backend de muxage » vaut désormais **Auto**, qui choisit l'assembleur Matroska natif pour toute sortie `.mkv` que le plan permet ; FFmpeg reste au choix (Paramètres, panneau Conteneur, `--mux-backend`, champ `mux_backend` d'un job). Un réglage FFmpeg enregistré par une version précédente (ancien défaut) passe une fois à Auto, journalisé ; une valeur `ffmpeg` écrite dans `config.ini` est respectée.
  * **Entrelacement exact** : chaque piste est lue à son rythme et les paquets sont écrits dans l'ordre des horodatages, quelle que soit la disposition des sources. L'audio et les sous-titres pris dans une autre source que la vidéo ne sont plus écrits des minutes en avance (lecture et déplacement dans la piste corrigés), synchro comprise ; un remux natif d'un fichier mal entrelacé le remet en ordre.
  * **Filet de sécurité** : si Auto doit encore passer par FFmpeg (cas non pris en charge par l'assembleur natif) et que la sortie `.mkv` est mal entrelacée, elle est réassemblée nativement avant publication, après vérification que la copie est fidèle (mêmes paquets, métadonnées, chapitres, tags, pièces jointes) ; sinon (espace disque, copie non fidèle) le fichier FFmpeg est publié avec l'avertissement. FFmpeg choisi explicitement : avertissement seul.
  * **Synchro réécrite assemblée en natif** : une piste décalée réécrite (silence ajouté, coupe, calibration multi-segments, sous-titres décalés) ne force plus le muxage FFmpeg ; même décision et mêmes pistes réécrites que le backend FFmpeg, placées comme lui, provenance (tags, nom, langue) conservée.
  * **Pistes MP4 / MOV lues en flux** : vidéo, audio et sous-titres d'une source MP4 / MOV copiés sans fichier intermédiaire (plus de remballage complet de la vidéo dans le dossier de travail), à la vitesse du muxage FFmpeg (film 2160p de 20 Go : 14 s contre 13 s).
  * **Échelle de temps 1 ms** dans toutes les sorties Matroska : les builds FFmpeg récents (master, embarqués dans les paquets AllInc) écrivaient 10 µs par défaut, avec dix fois plus de Clusters et un fichier refusé par l'étape Dolby Vision du Merge DoVi.
* **Avertissements de muxage.** Le journal signale une sortie dont une piste reste écrite en retard sur les autres (au-delà de 2 s) et plusieurs pistes d'un même type marquées « par défaut » ; rien n'est modifié.
* **Version de FFmpeg consultable.** Les paquets AllInc consignent la build exacte de FFmpeg / FFprobe embarqués (version, libavformat / libavcodec, date de l'asset) dans `tools-manifest.json` ; info-bulle des badges « Outils disponibles » du tableau de bord (clic droit « Copier les versions des outils »), ligne « FFmpeg : … » en tête de chaque Remux / Encodage / Merge DoVi, et `--cli tools --versions`. Les paquets et la CI utilisent FFmpeg master (FFmpeg-Builds), sans repli vers une autre source.

## Correctifs

* **Remux, synchro réécrite avec variante audio** : une piste décalée convertie dans un autre codec n'est plus encodée deux fois (la réécriture produit directement la variante, passage en 5.1 de l'AC-3 compris) ; réécriture lancée sur la piste d'origine avant la synchro timeline des pistes étrangères.
* **Encodage avec synchro multi-sources en direct** : une piste synchronisée transmise par FIFO (Linux, macOS) était lue comme du Matroska alors qu'elle est écrite en NUT, et l'encodage échouait.
* **Encodage, muxage FFmpeg** : les sous-titres d'une source qui fournit aussi l'audio, mais pas la vidéo, sont lus par une entrée à part ; un sous-titre clairsemé ne fait plus écrire l'audio en avance sur la vidéo.
* **Sorties jamais écrasées sans autorisation, même en parallèle** : sans `--force`, une sortie n'est plus remplacée quand deux traitements visent la même destination en même temps (deux commandes, plusieurs jobs d'un worker `serve`) : le second est refusé (`output_exists`, ou `busy` pendant l'écriture du premier). Vaut pour les médias (remux, encodage, extraction, `hdr-patch`) et les documents écrits par le CLI (calibrations, presets exportés, sous-titres recalés).
* **Interface : seul le fichier confirmé est remplacé** : si la destination apparaît, change ou devient un lien vers un autre fichier entre la question « Remplacer ? » et l'écriture (encodage, remux, extraction, Merge DoVi, HDR Studio), elle n'est plus remplacée : rien n'est écrit et un message invite à relancer pour confirmer à nouveau.
* **Extensions pendant un traitement** : installer, mettre à jour ou supprimer une extension (moteur vidéo MVO, TensorRT, FEL, NVEncC) est refusé pendant un traitement, un aperçu ou une analyse HDR Studio, et rien de cela ne démarre pendant une installation ; les mises à jour automatiques attendent la fin du traitement, et un outil changé entre-temps sert au traitement suivant.
* **HDR Studio, édition des métadonnées : images sans RPU** : une image Dolby Vision sans RPU reçoit le RPU de l'image précédente, à sa place exacte dans l'ordre d'affichage, et le journal le signale (avertissement `dovi_rpu_completed` en CLI et dans l'API) ; auparavant, l'outil comblait les manques sans le dire, parfois avec le RPU d'une autre image.
* **FEL Analyzer, aperçu et extraits FEL : couche EL aux images clés décalées** (extension mvo-fel 0.6.1) : sur une source dont les images clés de la couche EL ne suivent pas celles de la BL, le positionnement échouait (« Envoi couche au décodeur : Invalid data found ») ; chaque couche est désormais décodée depuis sa propre image clé et l'image livrée est celle d'une lecture complète. Un extrait coupé avant la première image clé de l'EL rend ses premières images sans résiduel, comme un lecteur Dolby Vision, et le journal le signale.
* **`config.ini` et séparateurs de ligne Unicode** : une valeur contenant U+2028, U+0085 ou un autre séparateur de ligne est refusée ; une valeur existante qui en contient un n'est plus scindée en options parasites à l'enregistrement d'une autre option.
* **CLI : `batch` et lots de profils sans `--continue-on-error`** : le lot s'arrête désormais après le premier job en échec, quelle qu'en soit la cause (auparavant, seul un job impossible à préparer l'arrêtait ; un remux ou un encodage refusé laissait continuer les suivants), comme l'annonce l'option. Le bilan liste les jobs lancés ; `--continue-on-error` garde l'ancien enchaînement.
* **Panneau Encodage, HDR10 et tone mapping** : une source SDR ou HLG n'est plus marquée HDR10 (PQ) par une valeur héritée de la source, ni dans l'aperçu ; une valeur saisie (ou choisie dans HDR Studio) reste une saisie, jamais remplacée par la mesure de l'intégration FEL, jusqu'à son remplacement par la valeur de la source (Copy, « Valeurs source », nouvelle source) ; avec « Appliquer à toutes », le tone mapping automatique suit chaque source quelle que soit la piste affichée, et un choix explicite (coché ou décoché) est gardé aux changements de codec et à Copy, comme `tonemap.enabled` en CLI.
* **Titres et langues de pistes vidés** : effacés à l'encodage, variantes audio comprises (le titre de la source, ou sa langue, réapparaissait en sortie) ; capturés dans un profil décisionnel et rejoués à son application (case « Effacer » de l'éditeur, `clear` sur `create_audio_variant`) ; les règles capturées retrouvent leurs pistes par la langue et le titre lus dans le fichier (nouveaux champs `file_language`, `file_title` ; une variante garde ceux de son flux), y compris sur un tableau déjà modifié ou à une deuxième application (profils capturés auparavant : à recapturer) ; reprise des variantes inchangée pour les profils sans effacement, variantes effacées propres à leurs demandes ; l'éditeur de profils ne réécrit que les actions et critères modifiés (critères vidéo modifiés en place). Hybrid : un modèle témoin contenant une variante audio n'échoue plus (variante recréée par le profil, y compris après export de la recette ; sans profil, refus explicite) ; une recette portant des variantes ajoute deux clés que les versions antérieures refusent. Le drapeau Matroska « piste activée » (`FlagEnabled`) est conservé par l'export exact-job, la reprise de session, l'export Hybrid et les variantes créées par un profil (`flags.enabled`).
* **Extraction de sous-titres VobSub** : livrée en Matroska (`.mks`), FFmpeg ne sachant pas écrire `.idx` / `.sub` (l'extraction échouait).
* **Paramètres avancés saisis à la main** : reportés dans le dialogue pour tous les encodeurs (option inconnue conservée ; exclusions NVEncC sans erreur à l'ouverture).
* **Cadence** : la valeur aberrante `500/21` renvoyée par ffprobe pour certaines sources est interprétée comme 23,976 i/s.
* **Synchronisation audio** : sélecteur de flux FFmpeg numérique accepté.
* **TMDB** : jeton d'accès (*bearer*) reconnu lorsqu'il est saisi dans le champ de la clé d'API.
* **macOS** : bibliothèques Qt collectées par les crochets PyInstaller ; signature du paquet final vérifiée.
* **Encodage : champs de filtres bornés** : mode, parité et sélection du désentrelacement YADIF, algorithme de tone mapping… limités à leurs valeurs, quelle que soit leur origine (job, preset, API) : une valeur libre cassait la commande ou pouvait y ajouter un filtre.
* **Paramètres : ancien réglage du journal fichier** (`verbose_file_logging`) conservé par une écriture partielle de `[ui]` (journal ouvert au démarrage, popup de mise à jour, `config set`) : il était supprimé sans être remplacé, ce qui désactivait le journal fichier.
* **Redémarrage proposé après un changement d'échelle ou la relance du setup** : la nouvelle instance n'est lancée qu'après l'accord de fermeture (opération en cours comprise), puis l'instance courante se ferme (après le setup, elle restait ouverte).
* **Paramètres : message d'état** : un second enregistrement ou un changement de langue réaffichait le premier message de la session.

## New features

* **MVO-R2 denoising (MVO video engine 1.15.0).** A new learned denoiser, now the default in the Encoding panel's "Denoise" filter (NLMeans remains available). Each frame is denoised from a window of 5 frames aligned by the network's own optical flow: grain and noise are removed while detail confirmed by neighbouring frames is kept.
  * **Levels**: *Auto* (strength decided shot by shot from the measured grain: a clean source is barely touched), *Light*, *Medium*, *Strong*. Animated content (TMDB "Animation" genre, or manual setting): Auto removes one step more.
  * **Sharpness compensation** ("Sharpness" list, on by default): restores part of the fine detail removed by denoising, only where it is stable from frame to frame — never the grain, never more than what was removed.
  * **Auto mode (default)**: fast mode above 2560 px wide — in UHD it keeps the same detail as normal mode in about a third less time — and normal mode below. Fast mode: optical flow computed at a quarter of the resolution.
  * **HDR**: 10-bit processing; source MaxCLL / MaxFALL kept when denoising does not visibly change them, otherwise measured on the denoised picture; Dolby Vision and HDR10+ copied and checked frame by frame; compatible with Dolby Vision FEL layer integration.
  * **Denoising then interpolation** in a single pass when MVO-RIFE is also enabled.
  * **NVIDIA TensorRT**: accelerated denoising with the `mvo-rife-trt` 1.3.0 extension (automatic Vulkan fallback).
  * MVO-R2 is demanding: in 4K, it sets the speed of the encoding chain.
* **HDR10+ generated from Dolby Vision.** New Encoding panel option "Generate HDR10+ metadata from Dolby Vision", offered for any Dolby Vision source with a PQ base layer, with every codec that carries HDR10+ (x265, NVENC, QSV, VAAPI, AMF, NVEncC HEVC and AV1) and in **Copy** (stream patched without re-encoding: RPU, enhancement layer and Dolby Vision signalling untouched). For TVs without Dolby Vision (Samsung…).
  * **Measured values**: statistics of every frame (MaxScl, average, distribution, profile A) measured by the `mvo-fel` extension, one scene per Dolby Vision shot, with the rules of the FEL integration's recomputed HDR10+; the HDR Studio measurement cache is reused when available. With FEL integration: the reconstructed picture. Without the extension or for a P5 source: estimated from the RPU L1, reported as approximate.
  * **Isolated peaks**: MaxScl no longer follows the few pixels that clearly exceed the rest of the picture (above 2 × the 99.98th percentile and 1000 nits); on a 600-nit TV, a shot's highlights are no longer compressed by a single specular highlight. Same rule for the FEL integration's recomputed HDR10+ and HDR Studio's recompute; HDR Studio's realignment no longer reports these isolated pixels as clipping.
  * **Replaces** the source HDR10+ (exclusive with "Copy HDR10+ metadata"); works with filters, MVO-R2, MVO-RIFE (metadata extended to the output frame rate) and FEL integration; frame counts checked before injection. Exceptions, as with HDR10+ copy: NVEncC does not accept filters run through FFmpeg (deblock, chroma_smooth, crop or resize in %) outside FEL integration — pick an FFmpeg encoder (x265, NVENC…); in Copy, a raw HEVC source (`.hevc`, `.h265`…) is refused as it has no timestamps — remux it to MKV first or re-encode.
  * **CLI / API**: `--hdr10plus generate`, `hdr10plus.mode: generate` in the `encode` block, encoding presets.
* **YADIF "one frame per field" deinterlacing without interpolation**: copied Dolby Vision / HDR10+ metadata now follow the doubled frame count (they used to cover only half of it), including with NVEncC's native filter.
* **"MVO video engine (denoising, interpolation)" extension.** The `mvo-rife` extension now provides both processes and is listed under this name on the Extensions page.
* **AllInc NoVidia variant and NVEncC in Extensions.** New `Muxiveo-x86_64_allinc_novidia-<version>.AppImage` and `Muxiveo-Setup-AllInc_NoVidia-<version>.exe` packages: identical to AllInc without NVEncC, which is installed on first launch when an NVIDIA GPU is detected (Linux: apt / dnf with the administrator password, otherwise the user folder, notably on immutable distributions; Windows: user folder). NVEncC can also be installed, updated and removed from the "NVEncC" card of the Extensions page.
* **x265: *frame-threads* setting** (number of frames encoded in parallel, automatic by default). The FFmpeg thread count is no longer applied to libx265, which always uses every core (limit it with `pools=N` in the track parameters).
* **x265: new advanced parameters**: `qg-size`, `deblock`, `qcomp`, `cbqpoffs` / `crqpoffs`, `b-intra`, `rc-lookahead`; disabled options (`no-…`) and values outside the widget ranges are read back and kept.
* **Failed encode with temporary files.** When an encode started from the interface fails after producing files, a dialog offers to keep the work folder for inspection; otherwise it is removed in the background.
* **Encoded image preview.** The Encoding panel's image preview now shows the frame of the **encoded output** at the chosen (or random) instant, with every track setting (filters, crop, resize, HDR, FEL, MVO-R2, interpolation), instead of the gallery of seven source scenes; the frame shown is the first one from that instant, based on its real timestamps. Same preview in the CLI (`encode --preview-image`) and the API.
* **Settings in tabs.** One section per tab (Interface, Audio encoding, Synchronization, Metadata, Paths, External tools, FFmpeg, Encoding, Matroska muxing), fields sized to their content, and a single "Save" button for the modified tab, marked with a dot. Leaving the tab or the page with unsaved changes — including by starting an operation, dropping a file, installing an update, restarting, reloading `config.ini` or closing the application — offers to save them, discard them or cancel (nothing is started then). Only modified values are written, the others keep their source; a `config.ini` value the field cannot display (between steps, unknown option, out of range) is kept as is until it is edited. A saved tool path applies to the next processing (encoding, Merge DoVi) without restarting.
* **Options without effect removed.** `[tools] eac3to`, used by no processing (no longer reported as a missing tool on the dashboard or at startup), `[hdr] dovi_profile` / `dovi_compat_id`, already flagged as unused, and `[encoding] ram_buffer_enabled` (the RAM buffer was no longer used: the option only changed a log message) leave Settings, the CLI `config` command, the `system.tools` operation and setup; their lines are removed from `config.ini` the next time the configuration is saved. "RAM buffer threshold" becomes "Free RAM reserve": share of RAM kept free to start one more parallel video encode. The simulated display peak (HDR tab) is set in HDR Studio (Luminance tab), which remembers the last choice; a `[hdr] display_peak_nits` key in `config.ini`, which hid that choice after a restart, is ignored.
* **CLI: service layer and `call` command.** Every CLI feature is an operation (56) with a stable contract, the basis of the `serve` worker: `operations` lists the catalog, `schema --version api` publishes it as JSON, `call <operation> --request file.json` (or `-` for stdin) runs a strict JSON request, job and `encode` block included (field-level errors), and replies in JSON (final state and exit code of a batch from its status: 7 unless it fully succeeded). New `--log-format events`: log, progress and result as versioned events. Existing command outputs are unchanged, except for the compatibility changes below and a warning now emitted for a JSON job key outside the contract (what the contract accepted is still accepted). GUI parity sheet: `docs/cli/parite-gui.md`.
* **CLI: Ctrl+C cleanly cancels a remux or a batch.** `remux` / `run` / `profile apply` stop like a cancellation from the GUI: processes stopped, partial file and work folder removed (exit code 6). During a `batch`, the current job is cancelled and the batch stops; already published outputs are kept and the summary says so (`cancelled`, exit code 7). Every CLI command is now a service-layer operation callable through `call` (batches: one child job per file, `succeeded` / `partial` / `failed` / `cancelled` status). Ctrl+C also cancels `inspect --hdr` (from the file reading on, HDR measurement and FEL Analyzer included) and `hdr-patch`, and stops `hybrid`.

Same rules as the Encoding panel (defaults from the source, per-codec HDR policy, an incompatible preset refused as when it is loaded); **default rendering**: an HDR source encoded to a codec without HDR (H.264…) is converted to SDR (tone mapping checked automatically, as in the panel; `tonemap.enabled: false` prevents it), and the HDR10 / Dolby Vision / HDR10+ options removed for that codec are restored when going back to an HDR codec; `validate --json` publishes the resolved plan and the same refusals as at launch, `--dry-run` the planned commands. New `capabilities` command: encoders, presets, Vulkan, NVOF, TensorRT, MVO video engine. Encoded image and video previews (`encode --preview-image` / `--preview-video`), GUI encoding presets managed from the CLI (`encode-preset list|show|save|import|export|delete`), work folder of a failed encode can be kept (`--keep-failed-work-dir`).
* **Track, Dolby Vision layer and attachment extraction.** Right-click in the Container panel: "Extract…" on an audio or subtitle track, "Extract" submenu on a video track (video stream, FEL / MEL enhancement layer and base layer of a Dolby Vision profile 7, Dolby Vision RPU, HDR10+ metadata), "Extract…" on an embedded attachment. Elementary stream by default (HEVC / H.264 in Annex B, TrueHD, E-AC-3, DTS, FLAC, AAC…, PCM as WAV or AIFF depending on its format, without conversion) or Matroska on request. Same extraction from the CLI: new `extract` command (`--track`, `--layer el|bl|rpu|hdr10plus`, `--attachment`, `--all`, `--format raw|mkv`) and `media.extract` operation. Every output is written to a `.partial` file and then published: a failure or cancellation leaves nothing behind (publication refused by the file system or destination changed in the meantime: result kept and reported).
* **CLI: full HDR Studio.** New `hdr-patch` command (`hdr.patch` operation), the Edit tab's equivalent: MaxCLL/MaxFALL, mastering display, Dolby Vision RPU (L6, L5, L11, RPU mastering display, CM v4.0 removal), HDR10+ (removal, TSDML, profile A, cap, recomputation from the measurement), suggested values (`suggested`), "Keep identical" and realignment proposals from the measurement (`--realign`), resolved plan without writing (`--dry-run`). `inspect --hdr --hdr-advice` adds the recommendations (suggested values, TV tone-mapping simulation with `--hdr-display-peak` and `--hdr-tv-model`, realignment), also in the HTML report; `--hdr-fel-moments` writes the FEL Analyzer's most marked moments as full-resolution PNG files (without FEL, with FEL, difference).

New `calibration show|edit|compose|invert` command: cuts, silences, removed junctions, start offset or offset from a segment, cadence method ("auto" decided by pitch analysis), like the Sync Studio; `sync-waveform` publishes a track's waveform (data for a graphical client).

* **CLI: installing updates.** `version --install --yes` downloads, verifies and installs the channel's latest version (AppImage replaced at once; Windows installer, source archive and macOS application installed when the CLI exits), without relaunching the GUI; the previous update's report is shown.
* **CLI: full help and documentation.** Every option and command described (Sources, Output, Tracks, Sync, Encoding, HDR, TMDB, Log groups; default values; examples), home page by family, `help` command (`help COMMAND`, `help --all`, `help --format md`), help translated into the GUI language. Generated reference `docs/cli/reference.md`, task guide `docs/cli/README.md`, API `docs/cli/api.md` (operations, events, batches, errors), parity matrix `docs/cli/parite-gui.md`. `operations --describe` also lists the emitted events.
* **API: `serve` worker.** `muxiveo --cli serve` is a local machine entry point (JSON-RPC 2.0 over stdio, one JSON object per line) for an extension or a local tool started as a child process: job submission (`job.submit`), live events (`job.event`), cancellation by id (`job.cancel`), status (`job.get`, `job.list`), clean shutdown (`server.shutdown`). Jobs are scheduled by kind: media jobs (`--max-jobs`, 1 by default), analyses served during a long encode (`--max-analyses`, 2), configuration operations run alone. After an installed update, the worker announces its exit (`server.exiting`). Dependency-free example client: `docs/cli/examples/serve_client.py`; Python integration: `JobManager` (`core.service`).
* **API: typed contract.** `schema --version api` and `operations --describe` publish the schema of documents (job, `encode` block, decision profile, linked by `$ref`, the job closed like admission) and results (inspection record and tracks, extraction, batches, settings, presets, profiles, capabilities, extensions, TMDB…), the nature of each operation (`privileged`, `queue`) and, for events, each variant: warnings always carry a code (sync to review with its zones), progress steps with a stable id (`stage`) and a label (`label`), encoding progress (percentage, fps, frame, time left, track, pass) identical to the GUI's; in batches, each entry names its child job (`null` without a child job, e.g. a Hybrid episode only exported).
* **API: safe requests.** An API request (`call`, `serve`, Python) never implicitly uses a worker's current folder (relative values from the request file's folder — the current folder with `call --request -` — or the submission's `base_dir`, otherwise refused), refuses paths of another OS, accepts from a document no executable and no cover source outside TMDB, and limits free encoder parameters to the encoder's own options (inputs, outputs, formats, filters, progress and option-file loaders refused).
* **Compatibility changes.** `call` requires `--allow-privileged` for a privileged operation (`config.set/unset/reset`, `workdir.clean`, `nvencc.install/remove`, `plugins.install/update/remove`, `app.update_install`), otherwise a `forbidden` error (exit code 3); historical commands (`config set`, `plugins install`…) are unchanged. Without it, `config.show` / `config.get` redact the TMDB key and token (`********`). CLI text log: processing warnings are shown as `[WARNING]` (previously `[WARN]`).
* **Native Matroska muxing by default (Remux, Encode, Hybrid).** The "Mux backend" setting now defaults to **Auto**, which picks the native Matroska assembler for every `.mkv` output the plan allows; FFmpeg remains available (Settings, Container panel, `--mux-backend`, a job's `mux_backend` field). An FFmpeg setting saved by a previous version (former default) switches to Auto once, logged; an `ffmpeg` value written in `config.ini` is respected.
  * **Exact interleaving**: every track is read at its own pace and packets are written in timestamp order, whatever the layout of the sources. Audio and subtitles taken from another source than the video are no longer written minutes ahead (playback and seeking in the track fixed), sync included; a native remux of a badly interleaved file puts it back in order.
  * **Safety net**: when Auto still has to go through FFmpeg (a case the native assembler does not handle) and the `.mkv` output is badly interleaved, it is reassembled natively before publication, after checking the copy is faithful (same packets, metadata, chapters, tags, attachments); otherwise (disk space, unfaithful copy) the FFmpeg file is published with the warning. FFmpeg chosen explicitly: warning only.
  * **Rewritten sync assembled natively**: a rewritten shifted track (added silence, cut, multi-segment calibration, shifted subtitles) no longer forces FFmpeg muxing; same decision and same rewritten tracks as the FFmpeg backend, placed the same way, provenance (tags, name, language) kept.
  * **MP4 / MOV tracks streamed**: video, audio and subtitles of an MP4 / MOV source copied without an intermediate file (no more full video rewrap in the work folder), at FFmpeg muxing speed (20 GB 2160p film: 14 s vs 13 s).
  * **1 ms timestamp scale** in every Matroska output: recent FFmpeg builds (master, bundled in AllInc packages) wrote 10 µs by default, with ten times more Clusters and a file refused by the Dolby Vision step of Merge DoVi.
* **Muxing warnings.** The log reports an output where a track stays written behind the others (more than 2 s) and several tracks of the same type flagged "default"; nothing is changed.
* **FFmpeg version available.** AllInc packages record the exact build of the bundled FFmpeg / FFprobe (version, libavformat / libavcodec, asset date) in `tools-manifest.json`; tooltip of the dashboard's "Available tools" badges (right click "Copy tool versions"), "FFmpeg: …" line at the top of every Remux / Encode / Merge DoVi, and `--cli tools --versions`. Packages and CI use FFmpeg master (FFmpeg-Builds), with no fallback to another source.

## Fixes

* **Remux, rewritten sync with an audio variant**: a shifted track converted to another codec is no longer encoded twice (the rewrite produces the variant directly, AC-3 5.1 downmix included); rewrite run on the original track before the timeline sync of foreign tracks.
* **Encoding with live multi-source sync**: a synced track passed through a FIFO (Linux, macOS) was read as Matroska while it is written as NUT, and the encode failed.
* **Encoding, FFmpeg muxing**: subtitles of a source that also provides the audio, but not the video, are read through a separate input; a sparse subtitle no longer makes the audio be written ahead of the video.
* **Outputs never overwritten without permission, even concurrently**: without `--force`, an output is no longer replaced when two jobs target the same destination at the same time (two commands, several jobs of a `serve` worker): the second one is refused (`output_exists`, or `busy` while the first one is writing). Applies to media (remux, encode, extraction, `hdr-patch`) and to documents written by the CLI (calibrations, exported presets, shifted subtitles).
* **Interface: only the confirmed file is replaced**: if the destination appears, changes or becomes a link to another file between the "Replace?" question and the writing (encode, remux, extraction, Merge DoVi, HDR Studio), it is no longer replaced: nothing is written and a message asks you to run again to confirm anew.
* **Extensions during a job**: installing, updating or removing an extension (MVO video engine, TensorRT, FEL, NVEncC) is refused during a job, a preview or an HDR Studio analysis, and none of these starts during an installation; automatic updates wait for the job to end, and a tool changed in the meantime is used by the next job.
* **HDR Studio, metadata editing: frames without RPU**: a Dolby Vision frame without RPU gets the previous frame's RPU, at its exact place in display order, and the log reports it (`dovi_rpu_completed` warning in the CLI and the API); previously, the tool silently filled the gaps, sometimes with another frame's RPU.
* **FEL Analyzer, FEL preview and excerpts: EL layer with shifted keyframes** (mvo-fel extension 0.6.1): on a source whose EL keyframes do not follow the BL's, seeking failed ("Envoi couche au décodeur : Invalid data found"); each layer is now decoded from its own keyframe and the delivered frame is the one of a full read. An excerpt cut before the EL's first keyframe renders its first frames without residual, like a Dolby Vision player, and the log reports it.
* **`config.ini` and Unicode line separators**: a value containing U+2028, U+0085 or another line separator is refused; an existing value containing one is no longer split into stray options when another option is saved.
* **CLI: `batch` and profile batches without `--continue-on-error`**: the batch now stops after the first failed job, whatever the cause (previously only a job that could not be prepared stopped it; a refused remux or encode let the next ones run), as the option states. The summary lists the jobs that were run; `--continue-on-error` keeps the former behaviour.
* **Encoding panel, HDR10 and tone mapping**: an SDR or HLG source is no longer tagged HDR10 (PQ) by a value inherited from the source, nor in the preview; an entered value (or one chosen in HDR Studio) stays an entry, never replaced by the FEL baking measurement, until it is replaced by the source value (Copy, "Source values", new source); with "Apply to all", automatic tone mapping follows each source whichever track is displayed, and an explicit choice (checked or unchecked) is kept across codec changes and Copy, like `tonemap.enabled` in the CLI.
* **Cleared track titles and languages**: cleared when encoding, audio variants included (the source title, or language, reappeared in the output); captured in a decision profile and replayed when it is applied (editor "Clear" box, `clear` on `create_audio_variant`); captured rules find their tracks by the language and title read from the file (new `file_language`, `file_title` fields; a variant keeps those of its stream), including on an already edited table or a second application (previously captured profiles: capture again); variant reuse unchanged for profiles without clearing, cleared variants kept for their own requests; the profile editor only rewrites the actions and criteria you change (video criteria edited in place). Hybrid: a witness template containing an audio variant no longer fails (variant recreated by the profile, also after the recipe is exported; without a profile, explicit refusal); a recipe carrying variants adds two keys that earlier versions reject. The Matroska "track enabled" flag (`FlagEnabled`) is kept by exact-job export, session restore, Hybrid export and variants created by a profile (`flags.enabled`).
* **VobSub subtitle extraction**: delivered as Matroska (`.mks`), since FFmpeg cannot write `.idx` / `.sub` (extraction used to fail).
* **Manually entered advanced parameters**: carried into the dialog for every encoder (unknown options kept; NVEncC exclusions without an error on opening).
* **Frame rate**: the bogus `500/21` value reported by ffprobe for some sources is read as 23.976 fps.
* **Audio synchronization**: numeric FFmpeg stream specifier accepted.
* **TMDB**: access (*bearer*) token recognized when entered in the API key field.
* **macOS**: Qt libraries collected through PyInstaller hooks; final bundle signature verified.
* **Encoding: bounded filter fields**: YADIF deinterlacing mode, parity and selection, tone mapping algorithm… limited to their values whatever their origin (job, preset, API): a free value broke the command or could add a filter to it.
* **Settings: legacy file logging setting** (`verbose_file_logging`) kept by a partial `[ui]` write (log opened at startup, update popup, `config set`): it was deleted without replacement, which disabled file logging.
* **Restart offered after a scale change or a setup rerun**: the new instance is only started once closing is accepted (running operation included), then the current instance closes (after setup, it stayed open).
* **Settings: status message**: a second save or a language change displayed the session's first message again.
