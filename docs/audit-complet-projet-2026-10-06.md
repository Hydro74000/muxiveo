# Audit du projet Muxiveo — 6 octobre 2026

Audit transversal de l'arbre de travail basé sur **`6eadddf`**, version applicative **4.2.1**, incluant les modifications locales présentes au début de l'examen. **27 constats historiques** sont détaillés ci-dessous. Le tableau décrit l’état initial : A03 a été requalifié en compatibilité ancienne. Les corrections des onze lots et leurs validations sont suivies ci-dessous et dans le [rapport de relecture final](reaudit-11-lots-2026-10-06.md). Les principaux risques portent sur la propriété des fichiers temporaires, les collisions de sorties et les écarts entre interfaces et chemins d'exécution.

Périmètre : `core/`, `cli/`, `ui/`, `workers/`, points d'entrée, installation et packaging, workflows GitHub Actions, tests, documentation et sources de `native/muxiveo-rife`. L'outil séparé `mediamanager.py` est inclus et identifié explicitement. Les autres dépôts ouverts dans le workspace ne font pas partie de cet audit.

L’audit initial n’a appliqué aucune correction de production. Le complément demandé après revue des points A01, A03 et A04 est documenté dans [le réaudit](reaudit-lot7-seekhead-2026-10-06.md) : A01 est confirmé pour le candidat final, A03 est requalifié en compatibilité ancienne et A04 fait l’objet d’un correctif du binaire natif. Le plan de traitement est dans [le plan d’implémentation](plan-implementation-audit-complet-2026-10-06.md).

**Lecture des priorités et des preuves :** P1 = risque de perte de données ou de traitements perturbés à traiter en premier ; P2 = défaut fonctionnel, robustesse ou assurance qualité ; P3 = dette de maintenance/documentation. **R** = reproduction ciblée ; **L** = comportement établi par lecture du code ; **C** = constat de configuration ou d'analyse statique. Les conséquences conditionnelles sont distinguées du symptôme effectivement observé.

## Corrections existantes prises en compte

Les audits antérieurs ont servi de repères, pas de liste de bugs à recopier. Plusieurs de leurs constats ont changé dans l'arbre actuel : les sondes HDR d'encodage transportent désormais l'index de piste ; la validation examine les backends de toutes les vidéos ; le budget taille déduit déjà des flux copiés et répartit le reste ; le toggle HDR10 statique est séparé du tone mapping ; l'aperçu encode dispose d'un échappement par plateforme. Les problèmes A09–A10 concernent des cas résiduels de ce nouveau budget, et A13 le formateur remux distinct.

Le lot SeekHead dispose de tests supplémentaires et la suite complète passe avec ses modifications locales. Aucun des anciens défauts RV7 n'est réintroduit dans le tableau sans nouvelle preuve.

Les mécanismes déjà utiles comprennent les sorties candidates validées avant remplacement, le journal de restauration des éditions Matroska, les dossiers process créés avec jeton, la vérification SHA-256 des mises à jour applicatives et le TLS vérifié sans repli automatique. A01–A03 décrivent les limites de propriété et de concurrence restant autour de ces protections.

## Limites de l'examen

« Complet » désigne ici un audit de l'ensemble des sous-systèmes du dépôt, combinant revue ciblée, analyses statiques, suite existante et reproductions. Ce n'est pas une preuve exhaustive de l'absence d'autres défauts dans chaque branche du code.

Les 63 tests ignorés restent des limites de validation. Aucune exécution native Windows/macOS ni matrice exhaustive NVIDIA/AMD/Intel n'a été réalisée dans cette session. Le binaire RIFE local a été utilisé, et le lecteur Y4M a été recompilé isolément ; l'ensemble du moteur Vulkan n'a pas été reconstruit sous sanitizers. Les politiques GitHub distantes, l'historique des runs CI et les artefacts publiés n'ont pas été interrogés. Les constats de packaging portent sur les scripts présents, sans téléchargement ni publication.
